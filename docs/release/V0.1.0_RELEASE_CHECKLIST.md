# Kisab v0.1.0 Pre-Release Checklist

> **Status note:** This checklist gated the first production release. The `v0.1.0` signing workflow execution and artifact verification completed: the annotated tag exists, and release workflow run `30750947492` produced a production-signed APK that passed tests, lint, version/tag validation, and v2 signature verification. The GitHub release at `v0.1.0` was explicitly published by the owner (not a prerelease). The unchecked boxes below reflect the checklist's pre-release review state and are retained as history.

Use this checklist to gate the first production release. Every item must be **checked and verified** before the draft release is published. Any failure listed under **Stop conditions** must halt the release.

## Repository verification

- [ ] `git fetch origin && git checkout origin/main` — local checkout is on the latest `main`.
- [ ] Working tree is clean except for harmless local files (`.idea/`, `gradle/gradle-daemon-jvm.properties`).
- [ ] `./gradlew :app:testDebugUnitTest` passes.
- [ ] `./gradlew :app:lintDebug` reports **0 errors**.
- [ ] `./gradlew :app:assembleDebug` succeeds.
- [ ] `./gradlew -q :app:printVersionInfo` reports `versionName=0.1.0` and `versionCode=1`.
- [ ] Foundation dependency remains pinned to `com.susankhya.foundation:foundation-session-android:0.1.1`.
- [ ] `./gradlew :app:assembleRelease` without signing inputs fails with the intended clear message.
- [ ] `actionlint` passes on `.github/workflows/ci.yml`, `.github/workflows/release.yml`, and `.github/workflows/release-launch.yml`.
- [ ] No keystores, signing properties, generated APKs, `.sha256` files, or personal absolute paths are tracked.

## Protected environment configuration

- [ ] `release-signing` environment exists with the exact name.
- [ ] **Deployment branches and tags**: selected, permitting **only the branch `main`**, with **no tag patterns**.
- [ ] Administrator bypass is **disabled** (where supported).
- [ ] **Required reviewers** are configured with the release approvers.
- [ ] Self-review is prevented where supported; otherwise at least two reviewers are required.
- [ ] `main` is branch-protected with required pull-request review.

## Production keystore custody

- [ ] A permanent production keystore exists (created with `keytool`, RSA 4096, never the debug key).
- [ ] The keystore file is backed up to encrypted/cold storage.
- [ ] Keystore password, key alias, and key password are stored in the password manager.
- [ ] The base64 keystore form is stored only as the `KISAB_KEYSTORE_B64` environment secret.
- [ ] Secrets `KISAB_KEYSTORE_B64`, `KISAB_KEYSTORE_PASSWORD`, `KISAB_KEY_ALIAS`, `KISAB_KEY_PASSWORD` are set on the `release-signing` environment.
- [ ] No signing material or passwords appear in any commit, issue, or PR.

## Tag creation

- [ ] `v0.1.0` was created with `git tag -a` (annotated), not lightweight.
- [ ] `v0.1.0` points at a commit contained in `origin/main`.
- [ ] Tag name matches `v<versionName>` (`v0.1.0`).
- [ ] Tag was pushed: `git push origin v0.1.0`.

## Workflow approval

- [ ] `Release launcher` was run from `main` with input `v0.1.0`.
- [ ] `Release` workflow triggered on `repository_dispatch` (`release-signing-request`), not on a tag push or a manual dispatch from a non-`main` branch.
- [ ] `validate` job passed (annotated tag, commit contained in `origin/main`, tag did not move).
- [ ] `build-sign` requested environment approval and was **manually approved** by a reviewer.
- [ ] The run's trust context is `main` (`GITHUB_REF` = `refs/heads/main`).

## Artifact verification

- [ ] `build-sign` tests and lint passed on the validated commit.
- [ ] Tag matched packaged `versionName` (`v0.1.0`).
- [ ] APK was signed with the **production certificate** (verified with `apksigner verify --print-certs`); the certificate is **not** the debug key.
- [ ] APK SHA-256 was computed and attached.
- [ ] Downloaded APK checksum matches the attached `.sha256` value.

## Draft release review

- [ ] Draft release exists at tag `v0.1.0` with title `Kisab v0.1.0`.
- [ ] Draft target is the exact validated commit that produced the signed APK.
- [ ] Release notes match `docs/release/RELEASE_NOTES_0.1.0.md`.
- [ ] Draft contains the signed APK and the `.sha256` checksum.
- [ ] Draft is **not** auto-published; publication is still pending owner action.

## Publication

- [ ] Final manual verification of tag, target, certificate, and checksum completed.
- [ ] Clicked **Publish release** deliberately (no automation publishes).

## Post-publication verification

- [ ] GitHub release page shows `v0.1.0` as published with the correct notes and artifacts.
- [ ] `v0.1.0` tag is annotated and points at the intended commit.
- [ ] Download the published APK and confirm `apksigner verify` still passes and the SHA-256 still matches.
- [ ] Confirm the signed APK installs on a test device and `versionName=0.1.0`, `versionCode=1`.
- [ ] Confirm no signing secrets were exposed in Actions logs.

## Stop conditions

Abort immediately and do not publish if any of the following is true:

- Tag/version mismatch: the tag is not `v0.1.0` or does not match the packaged `versionName`.
- Lightweight tag: the tag is not annotated.
- Tag not contained in `main`: the tag points at a commit absent from `origin/main`.
- Unexpected certificate: the signed APK's certificate is not the production release certificate (or the APK is signed with the debug key).
- Missing or mismatched checksum: the `.sha256` file is absent or does not match the downloaded APK.
- Failed tests or lint errors: `testDebugUnitTest` fails or `lintDebug` reports any error.
- Unsigned APK: the produced APK is not signed.
- Non-`main` trust context: the signing run did not originate from the trusted `main` source (`repository_dispatch` from `main`).
